# 7. Критические бизнес-сценарии

[← План](06-roadmap.md) · [Оглавление](../README.md) · [Атрибуты качества →](08-quality-attributes.md)

Критические — сценарии, в которых сбой напрямую ломает бизнес-цель. Детальные сценарии использования (UC) будут в этапе 2 (артефакт 12).

| ID | Сценарий | Цели | Архитектурно значимые компоненты |
|---|---|---|---|
| SC-1 | Запись тренировки (в т.ч. офлайн, в «диких» местах, с устройствами) | BG-3 | Mobile, Ingestion, Activity |
| SC-2 | Просмотр результата и сравнение с собой/регионом | BG-3 | Activity, Analytics, Aggregates |
| SC-3 | Достижение → уведомление друзей → реакция группы | BG-1, BG-3 | Social, Notifications, Gamification |
| SC-4 | Массовое соревнование с live-лидербордом | BG-1, BG-3 | Competitions, Ingestion, CDN |
| SC-5 | Поиск напарников рядом/по маршруту с защитой приватности | BG-1, BG-4 | Discovery, Identity & Consent |
| SC-6 | Износ обуви → предложение → покупка в приложении магазина | BG-2 | Gear, Promo, Commerce Connector |
| SC-7 | Согласия, экспорт и удаление данных; родитель и ребёнок | BG-4 | Identity & Consent, все хранилища |

## SC-1. Запись тренировки
- **Актор:** пользователь (возможно без сети).
- **Предусловия:** авторизован, есть разрешения на геолокацию/датчики.
- **Основной поток:** старт → локальная запись с чек-поинтами → окончание → постановка в очередь синхронизации → отправка пачками (идемпотентно) → событие `ActivityRecorded` → сводка.
- **Альтернативы:** нет сети (хранение до 7 дней на устройстве); отключение датчика (запись продолжается с пометкой); ОС убила процесс (восстановление с последнего чек-поинта).
- **Критерии:** потери < 0,1%; приём пачки p95 < 500 мс; сводка доступна ≤ 30 с после синхронизации.

## SC-2. Сравнение с собой
- **Поток:** открыть тренировку → видеть темп/пульс vs. среднее за 4 недели и личные рекорды → (по желанию) положение в перцентилях региона.
- **Критерии:** p95 открытия сводки < 1 с на кэше; перцентили — только по когортам ≥ k=50.

## SC-3. Уведомление друзей
- **Поток:** достижение → правило «делиться» (по настройкам автора) → агрегация (не более N уведомлений в день) → push/лента → реакции.
- **Критерии:** доставка p95 < 30 с; пользователь не получает больше лимита; отключение в один шаг.

## SC-4. Массовое соревнование
- **Поток:** регистрация → старт → клиенты шлют пачки каждые 10–30 с → лидерборд обновляется, снапшот раз в 5 с через CDN → финал, проверка античита → публикация результатов.
- **Критерии:** до 500 тыс. одновременных участников (A-5); лидерборд отстаёт < 10 с; сбой в одном регионе не останавливает событие; ни одна запись не теряется (догрузка после события).

## SC-5. Поиск напарников
- **Поток:** пользователь включает «открыт к тренировке» на 2 часа → система предлагает совпадения по зонам/маршрутам/виду спорта (по грубой сетке, не по точным координатам) → взаимное согласие → контакт.
- **Критерии:** точные координаты не раскрываются; всё по согласию; авто-выключение статуса по TTL; жалоба и блокировка работают мгновенно.

## SC-6. Обновление обуви → покупка
- **Поток:** пробег пар ≥ порога → предложение (с учётом региона и согласия на маркетинг) → deep link в магазинное приложение (товар/промо) → покупка → атрибуция возвращается в аналитику.
- **Критерии:** атрибуция ≥ 90% завершённых переходов; недоступность магазина не ломает приложение (graceful degradation).

## SC-7. Приватность и удаление
- **Поток:** пользователь отзывает согласие / запрашивает экспорт или удаление → оркестратор удаляет данные во всех сервисах и производных хранилищах → подтверждение.
- **Критерии:** удаление ≤ 30 дней (цель 72 ч); агрегаты не восстанавливаются к человеку; аудит операций.
