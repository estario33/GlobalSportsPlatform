# ADR-013: Событийная шина (Kafka-совместимая) и политика managed-сервисов

[← Индекс ADR](README.md)

- **Статус:** принято (на утверждение архитектурным комитетом)
- **Дата:** 2026-10-25
- **Этап регламента:** 2

## Контекст
События связывают домены (ADR-001, ADR-009). Нужна переносимость между провайдерами (ADR-003).

## Решение
Шина — Kafka-совместимый брокер (managed у провайдера ячейки либо самоуправляемый кластер на платформе). Внутри ячейки — одна шина с топиками по доменам; схемы в registry; политика: ACL на топики, ретеншн по типу данных (сырые 7 дней, доменные 30 дней), DLQ. Платформенная команда ведёт перечень допустимых managed-сервисов; добавление — через заявку и оценку lock-in, затрат и безопасности.

## Рассмотренные альтернативы
- Облачные очереди провайдеров — не переносимы.
- Только синхронные вызовы — жёсткие связи и каскадные отказы.

## Последствия
+ переносимость, повторное чтение, независимость потребителей.
− эксплуатационная сложность Kafka; обучение команд.
Пересмотр: если managed-аналоги у всех провайдеров станут стандартом.
