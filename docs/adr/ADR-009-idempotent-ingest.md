# ADR-009: Идемпотентный ingest и контракт событий тренировки

[← Индекс ADR](README.md)

- **Статус:** принято (на утверждение архитектурным комитетом)
- **Дата:** 2026-10-25
- **Этап регламента:** 2

## Контекст
Клиент может повторять отправку; сеть нестабильна; множество потребителей данных. NFR-REL-02/03.

## Решение
Каждая пачка имеет идентификатор тренировки (UUID, генерируется на клиенте), порядковый номер пачки и контрольную сумму. Ingestion: проверка схемы → дедупликация по (activity_id, chunk_no) → запись пачки в объектное хранилище → публикация события в шину по транзакционному outbox. Ключ партиции событий — user_id (порядок в рамках пользователя). События версионируются (schema registry, обратная совместимость), потребители идемпотентны. Завершение тренировки — отдельное событие ActivityFinalized.

## Рассмотренные альтернативы
- Серверная генерация id — не работает офлайн.
- Exactly-once через распределённые транзакции — дорого.

## Последствия
+ безопасные повторы, простая эволюция.
− клиентская логика сложнее; нужна дисциплина схем.
Пересмотр: при росте числа потребителей > 15.
