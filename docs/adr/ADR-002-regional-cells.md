# ADR-002: Региональные ячейки и домашний регион пользователя

[← Индекс ADR](README.md)

- **Статус:** принято (на утверждение архитектурным комитетом)
- **Дата:** 2026-10-25
- **Этап регламента:** 2

## Контекст
Пользователи по всему миру (O1), законы о резидентности данных (RSK-03), задержки и изоляция отказов (NFR-SCL-05, NFR-REL-06).

## Решение
Система разворачивается как набор независимых **ячеек**: полный комплект сервисов и хранилищ для региона. Пользователь привязан к одной домашней ячейке (определяется при регистрации по стране/выбору; смена — через процесс миграции). Персональные данные хранятся только в домашней ячейке. Глобальный Directory хранит псевдоним → ячейка, без PII. Новая ячейка создаётся из шаблона IaC. Начальные ячейки: 1 (пилот), к фазе 2 — 3.

## Рассмотренные альтернативы
- Единая глобальная система — нарушает резидентность, единая точка отказа.
- Независимые страновые инстансы без федерации — рвёт глобальное сообщество.
Подробно: [10.2](../10-architecture-options.md).

## Последствия
+ соответствие законам, изоляция сбоев, предсказуемая стоимость на регион.
− федерация (ADR-007), дублирование операций, миграция при смене региона, сложнее глобальная аналитика (только агрегаты).
Пересмотр: при появлении юрисдикции, где нельзя использовать общий Directory.
