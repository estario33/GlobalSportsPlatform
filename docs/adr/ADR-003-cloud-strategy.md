# ADR-003: Облачная стратегия: единая платформа, провайдер на ячейку

[← Индекс ADR](README.md)

- **Статус:** принято (на утверждение архитектурным комитетом)
- **Дата:** 2026-10-25
- **Этап регламента:** 2

## Контекст
90% систем в облаках, провайдер не зафиксирован; ячейкам нужно присутствие в разных регионах; риск lock-in (RSK-15).

## Решение
Единая платформа: Kubernetes, Terraform/IaC, GitOps, единые стандарты безопасности и наблюдаемости. Ячейка целиком размещается у одного провайдера, выбранного по присутствию в регионе, цене и требованиям закона. Разрешены только managed-сервисы из утверждённого перечня с переносимым интерфейсом: Postgres-совместимая БД, Kafka-совместимая шина, S3-совместимое объектное хранилище, Redis-совместимый кэш, KMS. Сервис не размазывается между облаками.

## Рассмотренные альтернативы
- Один провайдер — нет присутствия везде, противоречит практике компании.
- «Лучший сервис у любого провайдера» — зоопарк, межоблачный трафик.
См. [10.3](../10-architecture-options.md).

## Последствия
+ переносимость, управляемая сложность.
− не используем уникальные сервисы провайдеров; нужна платформенная команда.
Пересмотр: ежегодно по стоимости/качеству провайдеров.
