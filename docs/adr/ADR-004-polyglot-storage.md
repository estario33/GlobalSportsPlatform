# ADR-004: Ограниченный полиглот хранилищ

[← Индекс ADR](README.md)

- **Статус:** принято (на утверждение архитектурным комитетом)
- **Дата:** 2026-10-25
- **Этап регламента:** 2

## Контекст
Данные разных классов: оперативные, телеметрия (объёмная), лидерборды (быстрые), аналитика.

## Решение
Четыре типа хранилищ: (1) реляционная БД Postgres-совместимая с гео-расширениями — оперативные данные, социальный граф; (2) объектное хранилище — сырые треки и телеметрия в сжатых колоночных файлах; (3) Redis-совместимый кэш — сессии, лидерборды, счётчики, TTL-статусы; (4) озеро/колоночное хранилище — аналитика и агрегаты. Новый тип хранилища — только через ADR. Графовая БД не вводится.

## Рассмотренные альтернативы
- Одна реляционная БД — не подходит для телеметрии.
- Свободный полиглот — рост сложности.
- Графовая БД — преждевременна при текущих объёмах связей.

## Последствия
+ каждый класс данных в подходящем месте, ограниченный набор технологий.
− несколько видов эксплуатации; согласованность между хранилищами через события.
Пересмотр: если глубина социальных запросов (друзья друзей) станет критичной.
