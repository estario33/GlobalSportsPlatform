# ADR-015: Карты: собственный тайловый сервис на открытых данных

[← Индекс ADR](README.md)

- **Статус:** принято (на утверждение архитектурным комитетом)
- **Дата:** 2026-10-26
- **Этап регламента:** 3 (по итогам анализа стоимости)

## Контекст
Приложение показывает маршруты на карте в каждой тренировке (FR-AN-01, FR-SC-02, FR-DS-02). Коммерческие картографические SDK тарифицируются за пользователя/загрузку карты; по модели [TCO](../16-tco.md) при вендорской модели расходы на 5-м году ≈ 4,9 млн USD/год против ≈ 0,3 млн при собственном сервисе.

## Решение
Векторные тайлы на открытых данных (OpenStreetMap и аналоги), стилизация под бренд, генерация и раздача из собственной инфраструктуры через CDN, оффлайн-пакеты регионов для «диких» мест. Геокодирование — собственное (открытый движок) либо точечно у вендора для поиска адресов (малый объём). Подготовку лицензионных условий и атрибуции ведёт юридический отдел.

## Рассмотренные альтернативы
- Вендорский SDK (MAU-тарификация) — быстрее на старте, но стоимость растёт линейно с аудиторией, плюс передача геоданных третьей стороне (QA-1).
- Гибрид: вендор на фазе 1, миграция на собственный сервис в фазе 2 — допустим как переходный план, если срок MVP критичен.

## Последствия
+ предсказуемая стоимость, нет передачи геоданных вендору, оффлайн-карты.
− нужна команда эксплуатации тайлов; качество POI/адресов ниже у вендоров; лицензионные обязательства ODbL.
Пересмотр: если качество карт критично для NPS (A/B на пилоте).
