# ADR-005: Нативные клиенты и offline-first синхронизация

[← Индекс ADR](README.md)

- **Статус:** принято (на утверждение архитектурным комитетом)
- **Дата:** 2026-10-25
- **Этап регламента:** 2

## Контекст
Ключевой сценарий SC-1: запись тренировок в фоне и без сети, BLE, HealthKit/Health Connect (O4). RSK-10: ОС может прерывать фоновые процессы.

## Решение
Модули записи, хранения, BLE и интеграции Health реализуются нативно (Swift, Kotlin). Запись идёт в локальную базу с чек-поинтами; синхронизация — очередь пачек с идемпотентными ключами, экспоненциальные повторы; хранение до 7 дней. Протокол синхронизации и контракты общие для платформ и покрываются общими тестами. UI в MVP тоже нативный; решение о кроссплатформенном UI пересматривается после фазы 1.

## Рассмотренные альтернативы
- Кроссплатформа целиком — риски фона/BLE.
- PWA — невозможна надёжная фоновая запись.

## Последствия
+ надёжность ключевого сценария.
− две кодовые базы; нужны общие контрактные тесты и тестовый парк устройств.
Пересмотр: после фазы 1 по метрикам потерь и скорости разработки.
