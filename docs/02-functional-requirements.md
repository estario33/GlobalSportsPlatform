## 2.1 Анализ исходных требований (R1–R11)

Регламент прямо говорит, что не все требования равнозначны. Приоритизация по MoSCoW с обоснованием; «MVP» = первая публичная версия (см. [план](06-roadmap.md)).

| Req | Суть | Решение | Обоснование / интерпретация |
|---|---|---|---|
| R1 | Социальные группы | **Must** | Центральный рычаг BG-1. Интерпретируем как группы по интересам с лентой и событиями; свободный чат — позже |
| R2 | Аналитика, сравнение | **Must** (с собой) / **Should** (регион) / **Could** (профи) | «Основное сравнение — с самим собой» (BG-3). Сравнение с регионом — перцентили на агрегатах. Профи — референсные агрегаты/лицензированные данные, не личные данные реальных людей |
| R3 | Поиск людей | **Should** | Высокая ценность, но высокая приватностная чувствительность. Поиск по интересам/месту/маршруту — opt-in, грубая геолокация. «Тренируются прямо сейчас» — только по явному статусу «открыт к совместной тренировке» |
| R4 | Инвентарь | **Must** | Прямая связь с BG-2 (замена обуви) и с планированием |
| R5 | Тренировки и расписание | **Must** (простые правила) / **Could** (ML) | MVP: шаблоны и правила; персонализация ML — после накопления данных |
| R6 | Уведомления друзей | **Must** | Дёшево, высокий эффект на BG-1/BG-3 |
| R7 | Геймификация | **Must** (базовая) / **Should** (расширенная) | Streaks, достижения, личные цели; турниры и лиги позже |
| R8 | Промо и новости по характеру тренировок | **Should** | Монетизация BG-2; требует накопленного профиля |
| R9 | Сторонние устройства | **Must** (health-платформы телефона и BLE-пульсометр) / **Could** (SpO₂, продвинутые) | Основная масса пользователей обойдётся данными телефона/часов через HealthKit/Health Connect |
| R10 | Интеграция с приложениями компании | **Must** (deep link/SSO/каталог) | Без этого не измеряется BG-2; встроенная корзина — non-goal |
| R11 | Региональные промоакции | **Should** | Реализуется конфигурацией того же Promo-движка (R8), отдельной подсистемы не делаем |

Особенности O1–O6 учтены как нефункциональные драйверы ([NFR](09-nfr.md)): O1 → региональные ячейки; O2 → live-соревнования и эластичность; O3 → расширяемость устройств; O4 → интеграция с HealthKit/Health Connect; O5 → безопасность и приватность; O6 → данная приоритизация.

Формат: ID — требование — приоритет — фаза ([план](06-roadmap.md)) — источник.

| ID | Требование | Прио | Фаза | Ист. |
|---|---|---|---|---|

| FR-ID-02 | Профиль: виды спорта, цели, уровень, регион, приватность по умолчанию «только друзья/группы» | Must | 1 | R1 |

## 2.3 Контроль сходимости

Всего 52 FR; Must — 27 (фаза 1 и два пункта фазы 2: FR-DV-01, FR-PL-01). Всё, что не прослеживается к R1–R11/O1–O6, отсутствует. Трассировка «R → FR → фаза → сценарий» ведётся в [плане](06-roadmap.md).
