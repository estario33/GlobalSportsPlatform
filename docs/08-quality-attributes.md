# 8. Атрибуты качества

[← Критические сценарии](07-critical-scenarios.md) · [Оглавление](../README.md) · [НФТ →](09-nfr.md)

## 8.1 Основные атрибуты (3, по лимиту регламента)

| ID | Атрибут | Почему главный | Бизнес-цели |
|---|---|---|---|
| **QA-1** | **Безопасность и приватность данных** | Геоданные и данные о здоровье — самый чувствительный класс; дети; законы разных стран. Нарушение блокирует все цели | BG-4 (и условие для BG-1, BG-2) |
| **QA-2** | **Масштабируемость и эластичность** | Пользователи по всему миру; массовые соревнования создают пиковые нагрузки в десятки раз выше средних | BG-3, BG-1, BG-4 |
| **QA-3** | **Модифицируемость и расширяемость** | Новые устройства, виды спорта, региональные промо, интеграции; «не все требования ясны заранее» | BG-2, BG-1 |

### Почему не выбраны другие
- **Наблюдаемость** — критична как *обеспечивающий* атрибут для QA-2 и QA-1 (см. 8.3), но самостоятельной бизнес-цели не отражает.
- **Доступность/надёжность данных** — для записи тренировки решается клиентской архитектурой (offline-first), поэтому серверные цели умеренные (99,9%), кроме ingest и соревнований (локальные атрибуты).
- **Стоимость** — ограничение, учитываемое в TCO на этапе 3.

## 8.2 Дерево полезности (сценарии качества)

**QA-1 Безопасность и приватность**
| Сценарий | Источник → Стимул → Реакция → Мера |
|---|---|
| Утечка точного места проживания | Другой пользователь ищет напарников → система не показывает точные координаты, зоны приватности маскируют начало/конец → 0 случаев раскрытия по тестам |
| Удаление данных | Пользователь запрашивает удаление → все сервисы и производные хранилища очищаются → ≤ 30 дней, цель 72 ч |
| Компрометация сервиса | Злоумышленник получает доступ к одному сервису → доступ ограничен его данными (изоляция, mTLS, минимальные права) → радиус ущерба = 1 домен |
| Нелегальный экспорт данных между регионами | Разработчик пытается прочитать данные чужой ячейки → политика отказывает, событие аудита → 100% запросов проходят политику |

**QA-2 Масштабируемость и эластичность**
| Сценарий | Мера |
|---|---|
| Старт крупного соревнования | Нагрузка вырастает в 20–50× за минуты → автомасштабирование приёма и снапшоты лидерборда → p95 приёма < 1 с, отставание лидерборда < 10 с |
| Рост базы в 10× за 2 года | Горизонтальное масштабирование доменов и ячеек → без переписывания; стоимость на MAU не растёт > 20% |
| Запуск нового региона | Новая ячейка из шаблона IaC → ≤ 4 недель без изменения кода |

**QA-3 Модифицируемость**
| Сценарий | Мера |
|---|---|
| Новый тип датчика | Разработчик добавляет коннектор → изменение только в Device Integration и справочнике → ≤ 2 недель, 0 изменений ядра |
| Новый вид спорта | Конфигурация метрик и справочника → ≤ 1 неделя |
| Региональная акция | Маркетолог создаёт кампанию и правила в консоли → публикация без релиза → ≤ 1 дня |
| Смена магазинной системы | Замена адаптера Commerce Connector → без изменений остальных доменов |

## 8.3 Обеспечивающие и локальные атрибуты

| Часть архитектуры | Дополнительные атрибуты | Комментарий |
|---|---|---|
| Клиент записи | Надёжность данных, энергоэффективность | Потери < 0,1%; расход батареи ≤ 8%/час |
| Ingestion | Идемпотентность, durability, пропускная способность | Приём пачек не теряется, повтор безопасен |
| Competitions | Доступность, консистентность результатов | Восстановимость итогов, прозрачные правила |
| Social/Notifications | Антиспам, модерируемость | Лимиты и жалобы |
| Promo | Соответствие согласиям, аудитируемость | Показ только при согласии |
| Вся система | **Наблюдаемость** (метрики, логи без PII, трассировка), тестируемость, управляемость затрат | Обеспечивает достижимость QA-1 и QA-2 |

## 8.4 Компромиссы между атрибутами

| Компромисс | Решение |
|---|---|
| QA-1 vs QA-3 (маркетинговая гибкость) | Таргетинг только по согласованным атрибутам; новые поля данных проходят ревью приватности |
| QA-1 vs QA-2 (глобальные агрегаты vs данные в ячейках) | Агрегаты строятся из анонимизированных потоков, k-анонимность; допускается задержка в сравнении с регионом (часы) |
| QA-2 vs стоимость | Дифференцированные SLO: live-путь дорогой, сводки — дешёвые и кэшируемые |
| QA-3 vs QA-2 (много мелких сервисов) | Укрупнённые доменные сервисы; дробление по измеренной необходимости |
| Консистентность vs доступность | Eventual consistency для ленты/уведомлений; сильная — для идентичности, согласий, результатов соревнований |
