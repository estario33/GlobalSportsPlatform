## 9.2 Нефункциональные требования

### Безопасность и приватность (QA-1)
| ID | Требование |
|---|---|
| NFR-SEC-01 | Все персональные данные шифруются при передаче (TLS 1.3) и в хранилищах (AES-256), ключи управляются KMS региона ячейки |
| NFR-SEC-02 | Персональные данные пользователя хранятся в ячейке домашнего региона; выход данных за границу региона возможен только по документированному правилу и аудируется |
| NFR-SEC-03 | Точные геокоординаты и трек недоступны другим пользователям без явного согласия; по умолчанию используются зоны приватности |
| NFR-SEC-04 | Аутентификация: OAuth 2.1/OIDC, MFA для привилегированных ролей, защита от подбора и подмены устройств |
| NFR-SEC-05 | Взаимная аутентификация сервисов (mTLS), принцип минимальных прав; доступ сотрудников к PII — по запросу, с аудитом и сроком |
| NFR-SEC-06 | Запросы на экспорт и удаление выполняются ≤ 30 дней (цель ≤ 72 ч), включая реплики, бэкапы по расписанию и производные данные |
| NFR-SEC-07 | Статистические сравнения публикуются только для когорт ≥ 50 человек (k-анонимность) |
| NFR-SEC-08 | Для несовершеннолетних по умолчанию закрытый профиль, без поиска и без маркетингового таргетинга |
| NFR-SEC-09 | Модель угроз (STRIDE/LINDDUN) пересматривается перед каждой фазой; pentest перед запуском и ежегодно |
| NFR-SEC-10 | Логи и метрики не содержат PII; корреляция по псевдонимам |

### Масштабируемость и производительность (QA-2)
| ID | Требование |
|---|---|
| NFR-SCL-01 | Система поддерживает рост до 30 млн MAU без смены архитектурного стиля (горизонтальное масштабирование доменов) |
| NFR-SCL-02 | Ingestion выдерживает пик 40 тыс. пачек/с на ячейку (соревнования) при p95 < 1 с |
| NFR-SCL-03 | Автомасштабирование: рост нагрузки в 20× за ≤ 5 минут для ingestion/лидербордов (предпрогрев по расписанию событий) |
| NFR-SCL-04 | Лидерборд соревнования отстаёт от реальности ≤ 10 с и раздаётся из кэша/CDN |
| NFR-SCL-05 | p95 API чтения (лента, сводка) < 500 мс в регионе ячейки; < 1,5 с для пользователя вне региона |
| NFR-SCL-06 | Новая ячейка разворачивается из шаблона IaC ≤ 4 недель |
| NFR-SCL-07 | Фоновая запись тренировки потребляет ≤ 8% батареи в час (GPS + датчик) |

### Модифицируемость и интеграции (QA-3)
| ID | Требование |
|---|---|
| NFR-MOD-01 | Новый коннектор устройства добавляется без изменений в других доменах и релиза клиента (там, где допускает платформа) |
| NFR-MOD-02 | Региональная кампания публикуется конфигурацией без релиза сервиса |
| NFR-MOD-03 | Контракты API и событий версионируются; обратная совместимость ≥ 2 версий клиента |
| NFR-MOD-04 | Интеграции с внешними системами только через адаптеры с контрактными тестами |
| NFR-MOD-05 | Каждый сервис собирается и развёртывается независимо; шаблон сервиса (golden path) включает логирование, метрики, безопасность |
| NFR-MOD-06 | Локализация: интерфейс и уведомления на ≥ 15 языках, единицы измерения и форматы по региону |

### Надёжность, доступность, данные
| ID | Требование |
|---|---|
| NFR-REL-01 | Целевая доступность основного API 99,9% в месяц; ingestion 99,95% |
| NFR-REL-02 | Потеря записанных на устройстве тренировок < 0,1% |
| NFR-REL-03 | Идемпотентный приём: повторная отправка не создаёт дубликатов |
| NFR-REL-04 | RPO ≤ 5 мин и RTO ≤ 1 ч для оперативных данных ячейки; для телеметрии — durability ≥ 99,999999999% (облачное объектное хранилище) |
| NFR-REL-05 | Сбой внешней интеграции (магазин, промо, устройство) не нарушает запись тренировок и ленту |
| NFR-REL-06 | Отказ одной зоны доступности не приводит к недоступности ячейки |

### Наблюдаемость и эксплуатация
| ID | Требование |
|---|---|
| NFR-OBS-01 | Трассировка запросов от клиента до хранилищ (с псевдонимами), RED-метрики на каждом сервисе |
| NFR-OBS-02 | SLO и error budgets на критические сценарии SC-1…SC-7; алёрты по burn rate |
| NFR-OBS-03 | Единая панель по ячейкам, стоимость по сервису и ячейке (FinOps-теги) |
| NFR-OBS-04 | Аудит доступа к PII неизменяем и хранится ≥ 12 мес. |

### Совместимость и ограничения
| ID | Требование |
|---|---|
| NFR-CMP-01 | Поддержка iOS и Android актуальных версий N и N-2; интеграции с HealthKit и Health Connect |
| NFR-CMP-02 | Доступность интерфейса (WCAG 2.1 AA) |
| NFR-CMP-03 | Облачная переносимость: ядро ячейки разворачивается у любого из допущенных провайдеров без изменения кода сервисов |
| NFR-CMP-04 | Технологический стек сервисов — из утверждённого перечня (≤ 3 языка в ядре), чтобы не создавать «зоопарк» |
